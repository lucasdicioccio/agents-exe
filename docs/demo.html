See it work: four agents on one screen

One prompt, “Give me the tour.”, goes to a front-desk agent. It asks three helper agents in the same turn; each helper runs a command-line tool of its own and reports back; the desk writes the answer. While that happens, agents-exe spectate shows the four sessions and their tool calls live.

Everything on this page was recorded on 2026-10-03 from a build of main, on a laptop, against a local model served by Ollama (gemma4:e4b). No hosted API and no real API key are involved, so you can run the same thing; the agents are in demo-agents/repo-tour/.

The agents

Four JSON files and three shell scripts:

AgentFileIts tool
repo-tour-deskdesk.jsonnone of its own; three helpers under extraAgents
code-countercode/agent.jsoncount_haskell: tracked .hs files and lines, per directory
historianhistory/agent.jsonrecent_commits: commit count and the latest non-merge commits
librariandocs/agent.jsonlist_docs: the pages under documentation/ with their titles

A helper reaches the model as a function (io_prompt_agent_<slug> in the frames above), the same way a tool does; see tools. Each tool is an executable that answers describe with its interface and run with its output; see executable tools.

Run it yourself

You need agents-exe built from the repository (getting started), Ollama running locally, and the model (ollama pull gemma4:e4b). Another model that your Ollama serves and that supports tool calls may work if you change modelName in the four JSON files; only gemma4:e4b was tried for this page. Run from the root of the repository: the tools describe the repository in the current directory, and the helpers’ tool directories are given relative to it.

# one shot: the answer on stdout
agents-exe --api-keys demo-agents/repo-tour/keys.json \
  --agent-file demo-agents/repo-tour/desk.json \
  run --prompt "Give me the tour."

keys.json holds a dummy key: Ollama does not check it, and agents-exe looks one up for each agent’s apiKeyId.

To watch it as above, use three terminals:

# 1. a server, with sessions in a SQLite file
agents-exe --api-keys demo-agents/repo-tour/keys.json \
  --agent-file demo-agents/repo-tour/desk.json \
  serve --db /tmp/repo-tour.db --port 8765 --stream-tokens

# 2. the read-only dashboard
agents-exe spectate --attach http://localhost:8765

# 3. start a session
curl -s -X POST localhost:8765/v1/sessions \
  -d '{"agent": "repo-tour-desk", "prompt": "Give me the tour."}'

The server has no authentication unless you give it --auth-tokens, and binds to 127.0.0.1 by default; see agents-server before exposing it.

What the recorded run did

  • The desk’s first turn asked for the three helpers in one go; the server created three child sessions, each linked to the desk’s session as its parent.
  • The run took 4 minutes 15 seconds from the session’s creation to its last update. That is the pace of an 8-billion-parameter model on a laptop, with the three helpers sharing one Ollama. It says nothing about agents-exe with a hosted model, which was not measured.
  • After the server was stopped and started again on the same database file, GET /v1/sessions still listed the four sessions with their parent links.
